9ui components live in your codebase, so you will restyle them, change them and add your own. The 9ui skills teach your AI agent to do that the way the library was built: every component follows one rulebook, and every change is checked against it.

A rulebook is a folder of Markdown rules for your components, kept in your project. It is yours. The skills never block a change. They ask, adapt and always tell you when a change is inconsistent with other components, breaks with real content or goes against a motion or accessibility standard.

## Installation

<Steps>

<Step>Install the 9ui skills.</Step>

```bash title="Terminal"
npx skills add borabaloglu/9ui
```

<Step>Install the skills they depend on.</Step>

```bash title="Terminal"
npx skills add emilkowalski/skills --skill emil-design-eng animate review-animations break-ui apple-design
```

The 9ui skills call these for design judgment, motion and worst-case testing. Without them the checks still run, with less depth.

<Step>Add a rulebook.</Step>

To use 9ui's rulebook, run `/rulebook-import` in your agent. To write one from your own components, run `/rulebook-create`.

</Steps>

## Commands

In Claude Code, each skill is a slash command. In other agents, ask for it by name.

### /new-component

Builds a component that matches the rest of your library, then checks it.

<Prompt text="/new-component a segmented control built on Base UI Toggle Group" />

### /update-component

Changes a component and tells you what the change means for its siblings.

<Prompt text="/update-component add an lg size to Select" />

### /review-component

Reviews a component, your current changes or the whole library. It changes no code.

<Prompt text="/review-component dialog" />

To review your uncommitted changes, pass `diff`. To review every component, pass `all`.

### /rulebook-create

Writes a rulebook from your own components. Where your components disagree, it asks you to choose. Where they give no answer, it uses general standards, not 9ui's style.

<Prompt text="/rulebook-create src/components/ui" />

The path to your components folder is optional.

### /rulebook-import

Downloads a rulebook into your project. With no argument, it imports 9ui's.

<Prompt text="/rulebook-import https://example.com/r/rulebook.json" />

You can also install 9ui's rulebook with the shadcn CLI.

```bash title="Terminal"
npx shadcn@latest add @9ui/rulebook
```

### /rulebook-update

Changes a rule, adds one or records why one component is different. It lists the components the change affects.

<Prompt text="/rulebook-update popups should open in 200ms" />

To let one component differ, ask for an exception. It's recorded on the rule with a reason and isn't reported again.

You can also edit the files by hand. The skills follow the new value from then on and report the components that still use the old one.

## The Rulebook

The rulebook is a folder of Markdown files in `.rulebook/` at your project root. Commit it with your code.

| File | Covers |
| --- | --- |
| `README.md` | Index and the list of roles |
| `surfaces.md` | Radius, fields, popups, modals, cards, color |
| `states.md` | Focus, hover, pressed, disabled, invalid, read-only |
| `sizing.md` | Heights, type, touch sizes, icons |
| `motion.md` | Curves, durations, enter and exit, reduced motion |
| `content.md` | Long text, missing data, small screens |
| `rtl.md` | Right-to-left layout |
| `accessibility.md` | What is required and what is optional |
| `code.md` | Typing, slots, variants, naming |
| `registry.md` | Demos, docs and registry entries |
| `decisions.md` | Every rule change, exception and accepted deviation |

Each rule has an id that never changes. A rule can also have a recipe, a reason, the standard it implements and the components that are exceptions.

```md title=".rulebook/motion.md"
### MOT-2 List every transitioned property

- **Recipe:** `transition-[scale,opacity]`, `transition-[background-color,border-color,box-shadow]`, or a named group such as `transition-colors`. Never `transition-all`.
- **Why:** `all` animates properties nobody chose, including layout.
- **Standard:** `STD-M2`
```

### Tailwind

Tailwind reads the rulebook like any other file in your project. To keep class names that appear only in the rulebook out of your CSS, exclude the folder in your main stylesheet. The path is relative to that file.

```css title="globals.css"
@source not "../.rulebook";
```

## Reports

Every report has the same five parts. For example:

```md title="Report"
## Review: select

**Findings**
- [Worst case] A long option label pushes the check icon out of the popup. `select.tsx:142` (CNT-3)
- [Consistency] None. Compared with Combobox and Menu.
- [Motion] None. Read the transition classes on the popup.
- [Accessibility] None.

**About the rules**
- `SIZ-8` says triggers are 36px tall; eight of ten components use 32px.

**Accepted**
- `STD-A2` Focus ring below 3:1, accepted 2026-11-15.

**Nice to have**
- Truncate the selected value with a tooltip.

**Not checked**
- A real touch device and a screen reader.
```

### What Is Always Reported

Some checks don't depend on your rulebook. Every report covers them, even after you choose to go ahead.

- **Consistency.** A part that differs from other components of the same role.
- **Worst-case content.** Long unbreakable text, missing data, large counts, small screens and right-to-left text.
- **Motion.** `transition-all`, scaling from zero, motion that ignores reduced motion, exits slower than entrances.
- **Accessibility.** Anything WCAG 2.2 AA requires.

To keep a deviation, accept it. It's recorded in `decisions.md` and listed in later reports as one line under **Accepted**.

Rules that most of your components don't follow are reported once, as a question about the rule.

Every report ends with what wasn't checked, such as a real touch device or a screen reader.

## Updating

To update the skills, run the update command.

```bash title="Terminal"
npx skills update
```

Updating the skills doesn't change your rulebook.
