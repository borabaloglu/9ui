Every 9ui component supports right-to-left layouts. Each component page has an RTL example with a language switch, so you can compare English with Arabic and Hebrew.

## Setup

<Steps>

<Step>Set `dir` and `lang` on `html`.</Step>

The `dir` attribute flips the layout. Change `lang` to your language.

```tsx {7} title="app/layout.tsx"
export default function RootLayout({
	children,
}: {
	children: React.ReactNode
}) {
	return (
		<html lang="ar" dir="rtl">
			<body>{children}</body>
		</html>
	)
}
```

<Step>Wrap your app in `DirectionProvider`.</Step>

`DirectionProvider` tells Base UI the reading direction, so arrow keys, sliders, carousels, calendars and popups that open to the side follow it.

```tsx {1,11} title="app/layout.tsx"
import { DirectionProvider } from "@base-ui/react/direction-provider"

export default function RootLayout({
	children,
}: {
	children: React.ReactNode
}) {
	return (
		<html lang="ar" dir="rtl">
			<body>
				<DirectionProvider direction="rtl">{children}</DirectionProvider>
			</body>
		</html>
	)
}
```

<Step>Add a font for your language.</Step>

Pick a font that covers your script. Noto pairs well with Inter and Geist. For Hebrew, use `Noto_Sans_Hebrew`.

```tsx {1,4-7,15} title="app/layout.tsx"
import { Noto_Sans_Arabic } from "next/font/google"
import { DirectionProvider } from "@base-ui/react/direction-provider"

const fontSans = Noto_Sans_Arabic({
	subsets: ["arabic"],
	variable: "--font-sans",
})

export default function RootLayout({
	children,
}: {
	children: React.ReactNode
}) {
	return (
		<html lang="ar" dir="rtl" className={fontSans.variable}>
			<body>
				<DirectionProvider direction="rtl">{children}</DirectionProvider>
			</body>
		</html>
	)
}
```

</Steps>

Not using Next.js? Set the same attributes in `index.html` and wrap your root in `DirectionProvider`.

```html {2} title="index.html"
<!doctype html>
<html lang="ar" dir="rtl">
	<body>
		<div id="root"></div>
	</body>
</html>
```

```tsx {1,6,8} title="src/main.tsx"
import { DirectionProvider } from "@base-ui/react/direction-provider"
import { createRoot } from "react-dom/client"
import { App } from "./app"

createRoot(document.getElementById("root")!).render(
	<DirectionProvider direction="rtl">
		<App />
	</DirectionProvider>,
)
```

## How it works

- Components use logical classes like `ps-2` and `ms-auto`, so spacing, icons and indicators follow `dir`.
- `DirectionProvider` drives behaviour: arrow keys, slider values, carousel scrolling, calendar navigation, and popups with `side="inline-start"` or `side="inline-end"`.
- Props that name a screen edge stay physical. `side="right"` is the right edge in both directions. See [Physical props](#physical-props).

## Right-to-left in part of a page

To show only part of a page right to left, set `dir="rtl"` on a parent element and wrap it in `DirectionProvider`.

Popups, dialogs, sheets and toasts render at the end of `body`, outside that parent. Set `dir="rtl"` on their popup part too.

```tsx {1-2,5} title="components/settings-menu.tsx"
<DirectionProvider direction="rtl">
	<div dir="rtl">
		<Menu>
			<MenuTrigger>القائمة</MenuTrigger>
			<MenuPopup dir="rtl">
				<MenuItem>تعديل</MenuItem>
			</MenuPopup>
		</Menu>
	</div>
</DirectionProvider>
```

The same goes for `DialogPopup`, `SheetPopup`, `SelectPopup`, `PopoverPopup`, `TooltipPopup` and every other popup part. For toasts, set `portalProps={{ dir: "rtl" }}` on `ToastProvider`. For Phone Input, set `dir="rtl"` on `PhoneInput`.

## Physical props

These props name a screen edge or corner, so they mean the same place in both directions.

| Component | Prop |
| --- | --- |
| Sheet | `side` |
| Drawer | `swipeDirection` |
| Vaul | `direction` |
| Sidebar | `side` |
| Toast, Sonner | `position` |
| Popups | `side="left"`, `side="right"` |

To open a sheet from the start in both directions, read the direction with `useDirection`.

```tsx {1,4,7} title="components/nav-sheet.tsx"
import { useDirection } from "@base-ui/react/direction-provider"

export function NavSheet() {
	const direction = useDirection()

	return (
		<SheetPopup side={direction === "rtl" ? "right" : "left"}>
			…
		</SheetPopup>
	)
}
```

To open a popup to the side of its trigger in reading order, set `side` to `inline-start` or `inline-end`.

```tsx {1}
<TooltipPopup side="inline-end">Settings</TooltipPopup>
```

## Writing RTL-ready code

### Spacing and position

To add space or position on one side, use logical classes. They give the same result as the physical ones in left to right, and flip in right to left.

| Physical | Logical |
| --- | --- |
| `pl-*`, `pr-*` | `ps-*`, `pe-*` |
| `ml-*`, `mr-*` | `ms-*`, `me-*` |
| `left-*`, `right-*` | `start-*`, `end-*` |
| `border-l`, `border-r` | `border-s`, `border-e` |
| `rounded-l-*`, `rounded-r-*` | `rounded-s-*`, `rounded-e-*` |
| `rounded-tl-*`, `rounded-tr-*` | `rounded-ss-*`, `rounded-se-*` |
| `text-left`, `text-right` | `text-start`, `text-end` |
| `scroll-ml-*`, `scroll-mr-*` | `scroll-ms-*`, `scroll-me-*` |

```tsx {3,5,7}
<div className="flex items-center gap-2">
	<Avatar />
	<div className="ms-2 text-start">
		<p>نورة</p>
		<p className="ps-1">مصممة</p>
	</div>
	<Badge className="ms-auto">جديد</Badge>
</div>
```

### Icons

To flip an icon that points in a direction, add `rtl:rotate-180`. This covers arrows, chevrons, back and next, and indent icons.

```tsx {3,7}
<Button>
	التالي
	<ArrowRightIcon data-icon="inline-end" className="rtl:rotate-180" />
</Button>

<Button variant="ghost" size="icon" aria-label="رجوع">
	<ChevronLeftIcon className="rtl:rotate-180" />
</Button>
```

To flip an icon whose lines would end up upside down when rotated, like text alignment icons, use `rtl:-scale-x-100` instead.

```tsx {1}
<TextAlignStartIcon className="rtl:-scale-x-100" />
```

Do not flip icons that look the same in every language: checkmarks, spinners, clocks, play and pause, search, and logos.

### Transforms and animations

Logical classes don't cover `translate-x-*`. To move something along the inline axis, add the opposite value under `rtl:`.

```tsx {1}
<div className="translate-x-full transition-transform rtl:-translate-x-full data-open:translate-x-0" />
```

### Text that stays left to right

Phone numbers, URLs, emails, versions and keyboard shortcuts read left to right in every language. To keep their order, wrap them in `bdi` or in an inner element with `dir="ltr"`.

```tsx {2,5}
<p>
	اتصل بنا على <bdi>+966 50 123 4567</bdi>
</p>
<div className="ms-auto">
	<span dir="ltr">https://9ui.dev</span>
</div>
```

Set `dir="ltr"` on an inner element, not on the element that has logical classes. `dir` changes how that element's own `ms-*` and `ps-*` resolve, so `ms-auto` would push it to the wrong side.

Keyboard shortcuts keep the order printed on the keys, so `⌘N` reads `⌘N` in both directions. `Kbd`, `KbdGroup` and the menu and command shortcut parts do this on their own.

### Numbers

To show digits the way a language writes them, format numbers with `Intl.NumberFormat`. Arabic often uses Arabic-Indic digits, so `12` becomes `١٢`. Hebrew uses Western digits.

```tsx {1}
new Intl.NumberFormat("ar-u-nu-arab").format(12)
```

## Third-party components

### Chart

Recharts doesn't read `dir`. To draw the X axis from the right and put the Y axis on the right, set `reversed` and `orientation`.

```tsx {1,4,5}
const direction = useDirection()

<BarChart data={data}>
	<XAxis dataKey="month" reversed={direction === "rtl"} />
	<YAxis orientation={direction === "rtl" ? "right" : "left"} />
	<Bar dataKey="desktop" />
</BarChart>
```

Known limit: bars in a group keep their left to right order, because Recharts draws them in data order.

### Calendar

Calendar reads the direction from `DirectionProvider`. Arabic short weekday names are wide, so to fit them in the day cells, use the narrow form.

```tsx {5-8}
import { format } from "date-fns"
import { ar } from "react-day-picker/locale"

<Calendar
	locale={ar}
	formatters={{
		formatWeekdayName: (day) => format(day, "ccccc", { locale: ar }),
	}}
/>
```

### Emoji Picker

Emoji Picker is built on [frimousse](https://frimousse.liveblocks.io). Translate the picker's own text, like the search placeholder, yourself.

Known limits:

- The emoji data has no Arabic or Hebrew translations, so emoji and category names stay in English.
- Arrow keys are not mirrored. Left moves to the previous emoji and Right to the next, in both directions.

### Resizable

Resizable is built on [react-resizable-panels](https://github.com/bvaughn/react-resizable-panels). Dragging and arrow keys follow the reading direction.

Known limit: in right to left, the handle's `aria-valuenow` and `aria-controls` describe the panel after the handle instead of the one before it.
